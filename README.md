# 纸本文物外借展陈 · 紫外灯光联动复核（静态站点）

保管员在浏览器录入 **2–6 个展柜**的：

- 滑动暴露窗口长度 `L` 与**最大窗口剂量限额**；
- **累计剂量上限**；
- 每柜纸张的**光损恢复系数 `k`（h⁻¹）**与**允许残余负担**（剂量复核合格后用于恢复复核）；
- 每柜 **3–8 盏灯**，每盏灯一个或多个**左闭右开**启停区间 `[启动, 停止)` 及该区间紫外照度。

系统在**连续时间**上把所有灯的区间叠加为**分段恒定照度**，对任意指定长度的连续滑动窗口
**精确求最大积分剂量**，并按展柜展示完整时段累计剂量、达到最大窗口剂量的**精确起止时刻**与
窗口内照度变化；超限时给出按**展柜输入顺序**、再按**违规窗口起点**稳定确定的**首项证据**。

剂量复核合格后，保管员可发起**恢复复核**：逐柜从展柜记录范围起点以**零负担**开始，
按已叠加的连续分段照度推演纸张**残余负担**——照射持续累积的同时，负担按该柜恢复系数
**连续衰减且不得低于零**——以此辨别**总剂量合格、却因短时连续照射而来不及恢复**的方案。


## 计算方法（不使用固定采样点）

- 全部数值用 **BigInt 精确有理数**保存与运算，不存在浮点误差；
- 所有灯的左闭右开区间端点合并为切分点，段内照度为覆盖该段的灯照度之和（分段恒定）；
- 窗口剂量 `D(s)=∫[s,s+L) i(t)dt`。在相邻「临界起点」之间 `i(s)`、`i(s+L)` 恒定，
  `D` 为线性函数，其最大值必在端点取得。临界起点恰为 `{切分点} ∪ {切分点 − L}`，
  只需在这有限的、精确的候选起点上求值，连续时间意义下精确；
- 最早违规临界时刻在每段上解一次一次方程得到，同样是精确时刻；
- 同值取最早起点，证据稳定可复现。

时间单位 h，照度 μW/cm²，剂量 μW·h/cm²。

## 恢复复核（残余负担连续推演）

- 仅在剂量复核**合格**后可发起；按钮在剂量结论缺失或不合格时禁用。
- 连续时间模型（无采样点）：自该柜记录范围起点 `t0`（最早点亮时刻）以 `B(t0)=0` 起算，

  `dB/dt = i(t) − k·B(t)`

  其中 `i(t)` 为全部灯左闭右开叠加后的分段恒定紫外照度，`k` 为该柜光损恢复系数（h⁻¹）。
  负担同时受照射累积与指数恢复，**始终不低于零**；黑暗段仅向 0 衰减。
- 每段照度恒定段内有解析解 `B(u) = i/k + (B(t)−i/k)·e^(−k(u−t))`，段内负担单调，
  故**峰值只可能出现在分段端点**（逐段比较即可，无需扫描时刻）；首次越限时刻由
  `B(u)=允许残余负担` 直接解出（该方程含指数，以双精度解析求值，时刻以 12 位小数精确记录）。
- 页面逐柜给出：残余负担**峰值及其发生时刻**、展期结束恢复后的残余负担、
  **每段起止负担**（与照度、灯号联动事件同表）；任一时刻**严格越过**允许负担即判越限，
  按**展柜输入顺序 → 首次越限时刻**返回稳定首项证据，并标明**越限时照度**与**恢复后负担**。
- 负担单位同剂量 μW·h/cm²；`i/k` 可能产生循环小数，这类结果页面以 6 位小数加 `…` 标示近似。

## 校验规则（非法时一次列出全部问题并阻止对应复核）

- 展柜 2–6 个、每柜灯 3–8 盏；
- 窗口长度、窗口限额、累计上限须为非负数值且大于 0；窗口限额不得大于累计上限；
- 灯号在同一展柜内不得重复、不得为空；
- 每个区间停止必须严格晚于启动；同一盏灯的区间不得相互重叠
  （端点相接合法：`[a,b) ∪ [b,c)`）；照度须为非负数值。
- 恢复参数（恢复复核前校验）：光损恢复系数与允许残余负担均须为**有限、非负且大于 0**
  的数值；缺失、`NaN`/`Infinity`、零或负数一次全部列出并阻止恢复复核。
  恢复复核同时包含全部剂量草稿校验——基础输入非法时同样阻止。

## 数据保存

草稿、**最近一次有效剂量复核结果**与**最近一次有效恢复复核结果**分别保存在本机浏览器
`localStorage`，关闭重开可继续调整。两类结论各带草稿指纹：

- 剂量相关草稿一旦修改，两类旧结论立即失效且不再显示；
- **仅修改恢复参数**时，恢复结论立即失效，而已合格的剂量结论保持显示、无需重新剂量复核；
- 需重新发起对应复核后方可再次查看结论。

## 本地开发

```bash
npm install --cache .npm-cache   # 如全局 npm 缓存目录不可写
npm test                         # 逻辑 + DOM 测试（node --test）
npm run dev                      # 开发服务器
npm run build                    # 生产构建到 dist/
npm run verify                   # 逻辑校验 + 生产构建 + 页面可访问检查
```

## Docker

```bash
# 宿主机端口可配置（默认 8080）
HOST_PORT=8080 docker compose up -d --build web
# 健康检查：GET /healthz

# 一次性校验服务：完成逻辑校验、生产构建、页面可访问检查后自行退出，
# 退出码报告结果（0 通过，非 0 失败）
docker compose up --build verify
docker compose inspect verify 2>/dev/null; echo $?   # 或 docker compose ps -a
```

`Dockerfile` 为多阶段构建：

- `web` 目标：nginx 托管 `vite build` 的静态产物，含容器健康检查；
- `verify` 目标：Node 镜像内运行 `scripts/verify.sh`
  （`npm test` → `vite build` → 对健康的 `web` 服务做 HTTP 可访问检查）。
